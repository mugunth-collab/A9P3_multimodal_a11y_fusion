# A9P3 - Multimodal On-Device AI Pipelines for Real-Time Accessibility Enhancement and Intelligent Screen-Reader Assistance in Mobile Applications

**Track:** Track 7  
**Application:** Accessible smart-city service apps for visually impaired users

This dataset is synthetic, generated by gen_author9.py with seed 2119. It must be described as synthetic in any publication.

## Simulated scenario

UI elements from six smart-city apps (transit, parking, waste pickup, 311 reports, EV charger finder, public Wi-Fi) are captured on several device tiers. Each element has view-hierarchy and visual features, outputs of on-device OCR/captioning/fused models, and runtime context (model size, latency, thermal, battery). Labels come from accessibility audits and blind user testing.

## How it was generated

Barrier latent (top ~28% after Gaussian noise) is mostly made of conjunctions of visual, text and UI-context conditions plus mild main effects (missing label, label quality, target size, dynamic content, focus order):

- Conjunction: icon-like element (icon/image button/image) AND no content description AND touch target <40 dp is an almost certain barrier; unlabelled but large icons are a weaker one.
- Conjunction: unlabelled non-icon element with no visible text (<2 chars) - nothing for the screen reader to announce; visible text largely rescues a missing label.
- Threshold: an existing label with quality <0.35 ("button", "img_23") misleads the user.
- Conjunction: live-updating map markers/charts are barriers when unlabelled OR outside the focus order.
- Regime: a broken focus order only matters in complex screens (hierarchy depth >11 or >8 siblings).
- Conjunction: text field AND font scale >=1.6 AND target <44 dp gets clipped.
- Conjunction: low contrast (<3) text that the OCR fallback cannot read (confidence <0.55).
- Latent sub-population: ~35% of Android elements in parking and public Wi-Fi apps are custom components inside a WebView whose labels are not exposed.

Description adequacy latent: fused confidence, model size, existing label, harder types for tiny models, low light, thermal throttling (top ~62%). Latency = model size x device speed x dynamic content x thermal.

Realism noise common to all numeric signals: ~5% multiplicative Gaussian measurement noise, 1-3% missing values in a few columns (empty cells), and ~0.5-1% injected outliers (listed per table below). Targets were computed from the noise-free latent signals, so the observed features are imperfect proxies.

## Target / label column(s)

`screen_reader_barrier` (binary ~28%), `ai_description_adequate` (binary ~62%), `inference_latency_ms` (regression).

## Suggested experiments

1. Barrier detection: GBM vs rule-based checker (missing label OR contrast<4.5 OR target<48dp); report F1, precision, recall.
2. Description adequacy by model size: accuracy/F1 and latency trade-off (Pareto) across tiny/small/base models and device tiers.
3. Adaptive model selection policy: choose model per element under a latency budget; report adequacy rate vs p95 latency.
4. Modality ablation (OCR only, caption only, fused + view hierarchy); report AUC.
